# Derived Assumptions — module-dashboard.screen-130--laporan-cages-track-web.3-tech-spec

## v1 — 2026-09-24

- `route` = `/reports/cages-track`, 4 endpoint ber-prefix `/api/cages-track-reports/*` ← konvensi repo `/reports/*` dan pola persis screen-129. User tidak menyebut rute maupun bentuk endpoint.
- **Endpoint sengaja dibuat walau layar ini bisa murni Livewire** ← agar screen-136 (versi mobile) memakai ulang sumber angka yang sama persis, seperti screen-135 memakai ulang `/api/sterilizer-reports/*`. Konsekuensi yang sudah diketahui: saat screen-136 dikerjakan, keempat route ini perlu dilebarkan menyertakan `operator`, sementara route web tetap tanpa operator.
- **`total_cages_out` dijumlahkan dari `cages_track_records.cages_out` (header), bukan dari baris rincian** ← diverifikasi langsung di migrasi: `cages_out` memang kolom header, satu per record. Agent penurun test spec semula menempatkannya di baris rincian. Menjumlahkannya di atas hasil JOIN ke rincian akan mengalikannya sebanyak jumlah baris jam; satu unit test khusus mengunci ini (50 dengan 8 baris rincian harus tetap 50).
- **Durasi jendela operasi dari selisih TIMESTAMP PENUH, bukan komponen jam** ← `tippler_start_time`/`tippler_stop_time` di-cast `datetime` dan diisi lewat `datetime-local` (`FormCagesTrack`), jadi shift malam sudah membawa tanggal berikutnya. Aritmetika melingkar modulo 24 hanya dipakai untuk HIMPUNAN jam operasi, karena `tipped_hour` adalah integer 0..23 tanpa tanggal. Turunan agent semula menyatukan keduanya sebagai "aritmetika melingkar", yang menghasilkan −18 jam untuk shift 22:00–04:00.
- **`stop <= start` diperlakukan sebagai jendela tidak dapat dihitung** ← `CagesTrackRecordService::validate()` hanya mewajibkan `['required','date']`, tidak ada `after:tippler_start_time`, jadi urutan terbalik dapat lolos. Tidak dinyatakan spec bisnis; dipilih agar laporan tidak pernah memancarkan durasi negatif.
- **`tippler_stop_time` NULL adalah kasus defensif, bukan jalur umum** ← validator hari ini mewajibkannya walau kolomnya nullable di skema. Aturan bisnis ke-10 tetap diimplementasikan penuh, tetapi tech spec menyatakan asalnya baris lama/impor supaya tidak ada yang mengira ini kejadian harian.
- **Sebuah tanggal berjendela pasti HANYA bila SELURUH record pada tanggal itu jendelanya dapat dihitung** ← satu tanggal dapat punya beberapa record (per `cages_track_number`), dan spec bisnis tidak menyebut apa yang terjadi bila hanya sebagian yang lengkap. Dipilih gagal tertutup: lebih baik tidak melaporkan daripada melaporkan angka yang diam-diam kehilangan sebagian jam operasi.
- **Jam penumpahan di-union lalu di-dedup antar record pada tanggal yang sama sebelum menghitung jeda** ← tanpa ini, jeda dihitung per record dan mill dengan dua track paralel akan selalu terlihat berjeda panjang padahal track lain sedang jalan.
- `days_without_valid_window` (bukan `days_without_stop_time`) ← nama dari turunan agent menyempit ke satu sebab; kenyataannya tanggal juga keluar karena `stop <= start`. Nama yang menyebut akibat, bukan satu sebabnya.
- **`peak_hour` dan `longest_gap_date` memilih nilai terkecil/paling awal saat seri** ← tidak diminta; tanpa aturan seri, hasilnya bergantung urutan baris dari database dan test bisa hijau-merah bergantian.
- `hourly` selalu 24 entri walau nol ← agar bentuk grafik tidak berubah antar periode. Tidak dinyatakan spec bisnis.
- **Seluruh agregasi di PHP, bukan SQL aggregate** ← disalin dari screen-129 dengan alasan yang sama: test berjalan di SQLite, produksi PostgreSQL, dan justru aturan null-bukan-nol yang paling mudah berbeda.
- Dua modifier CSS baru (`.md-kpis--3`, `.md-trendchart__col--off`) ditetapkan masuk ke `report-styles.blade.php`, bukan inline ← mengikuti keputusan penempatan CSS screen-140. Diturunkan dari mock, bukan dari spec.
- Daftar `data-testid` (mill-select, mill-current, period-select, report-hero, hero-status, report-kpis, kpi-total-tipped, kpi-total-out, kpi-avg-per-day, kpi-peak-hour, kpi-idle-hours, kpi-longest-gap, kpi-tippler-duration, days-without-valid-window, hourly-distribution, daily-trend, queue-card, daily-recap, empty-period, insufficient-gap, mill-required-hint, no-mill-for-account, no-periods, export-csv) ← ditetapkan agar component test dan browser test punya pegangan stabil; bukan permintaan user.
- `screen_dependencies` menyertakan `screen-140--laporan-stasiun-web` ← satu-satunya jalan masuk lewat UI. Tile-nya baru menyala setelah `REPORT_ROUTES` di `StationReportService` ditambah satu baris; tanpa itu laporan tidak terjangkau walau seluruh testnya hijau.

## v2 — 2026-09-24

Koreksi terhadap v1, ditemukan saat verifikasi pasca-implementasi.

- **Jeda terpanjang diurutkan menurut waktu berlalu sejak jendela operasi dibuka, bukan menurut nilai numerik jam** ← v1 menulis "selisih antar `tipped_hour` berturut-turut", yang benar untuk shift siang dan salah untuk shift malam. Terbukti dengan menjalankan service-nya: `longestGapOf([0,1,22,23])` mengembalikan **21**, padahal tippler 22:00→04:00 yang menumpahkan tiap jam tidak pernah berhenti lebih dari 1 jam. Kesalahan ini ada di spec, bukan di implementasi — agen mengimplementasikan v1 dengan setia. Keputusan user 2026-09-24: perbaiki sekarang.
- **Tanggal tanpa jendela yang dapat dihitung memakai urutan numerik** ← tidak punya jangkar, dan mengarang satu berarti mengada-adakan batas shift yang tidak pernah dicatat. Dipilih sebagai fallback eksplisit, bukan kebetulan; ada unit test khusus supaya tetap disengaja.
- **Jangkar = komponen jam dari `tippler_start_time` paling awal pada tanggal itu** ← satu tanggal bisa punya beberapa record dengan shift berbeda, dan spec tidak menyebut mana yang menentukan. Dipilih yang paling awal agar seluruh jam penumpahan hari itu jatuh setelah jangkar.
- `.md-trendchart` diperbaiki di luar cakupan screen-130 ← tinggi batang berbentuk persen tidak pernah ter-resolve karena kolomnya tidak bertinggi pasti, sehingga seluruh batang jatuh ke `min-height: 4px`. Diukur di peramban (batang 100% dan 25% sama-sama 4px), diperbaiki di partial bersama, diverifikasi di halaman asli (5 siklus → 95,7px, 7 siklus → 134,0px). Nol test menangkapnya karena asersi hanya memeriksa keberadaan elemen.
- **Asersi `laporan-stasiun.spec.ts` diturunkan menjadi invarian, bukan angka** ← test lama mengunci "tepat 1 tile aktif" dari zaman `REPORT_ROUTES` berisi satu entri. Diganti menjadi: aktif ⟺ punya href, nonaktif ⟺ tanpa href + "Belum tersedia", aktif + nonaktif = seluruh tile, minimal satu aktif dan satu nonaktif. Empat laporan stasiun lagi direncanakan di fase ini; angka keras akan merah empat kali lagi tanpa mengajarkan apa pun.
